# Plataformas e tratamento de falhas

## Portabilidade
Usar linguagem natural bilíngue por padrão. Quando uma plataforma for identificada, adaptar ênfase e formato aos recursos confirmados. Não inventar parâmetros nem dizer que todos os modelos aceitam prompt negativo. Manter conteúdo visual idêntico entre PT e EN.

## Links
A URL precisa permitir acesso e inspeção real da imagem. Página HTML pode exigir localizar a referência pretendida; se houver várias e nenhuma for indicada, solicitar a seleção. Falha de acesso exige upload ou novo endereço. Nunca pedir senha ou presumir sessão autenticada.

## Diagnóstico
| Falha | Ação |
|---|---|
| Imagem ausente | Pedir referência, sem inventar análise |
| Resolução insuficiente | Usar fatos distinguíveis e solicitar recorte só para detalhe essencial |
| Lado da luz traduzido errado | Fixar referencial de câmera e corrigir os dois textos |
| Dados de câmera especulados | Trocar afirmação por técnica equivalente sugerida |
| Muitas adições | Retornar às âncoras da fotografia |
| Prompt negativo incompatível | Omitir campo; usar restrições naturais se adequadas |
| Mudança de cenário não pedida | Restaurar elementos fixos |

Iterar uma mudança relevante por vez. Uma melhoria textual é hipótese; fidelidade do resultado requer imagem gerada e referência comparáveis.
